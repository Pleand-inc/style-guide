# RFC

이 저장소의 규칙, 설정, 플러그인은 RFC 로 바꿉니다. RFC 는 제안 문서와 변경을 함께 담은 pull request 하나입니다.

## RFC 가 필요한 변경

- 규칙 문서의 규칙 문장을 더하거나, 바꾸거나, 빼는 변경
- lint 설정, 포매터 설정, TypeScript 설정의 값을 더하거나, 바꾸거나, 빼는 변경
- lint 플러그인을 더하거나, 바꾸거나, 빼는 변경

규칙의 뜻과 검사 결과를 바꾸지 않는 변경에는 RFC 가 필요하지 않습니다. 오탈자 수정, 예시 추가, 워크플로 수정, README 수정이 여기에 듭니다.

## RFC pull request 에 담는 것

- 제안 문서 `rfcs/<이름>.md`
- 제안 문서가 적은 변경: 규칙 문장, 설정 값, 플러그인
- 더하거나 바꾼 규칙에 어긋난 코드와 규칙에 맞는 코드의 짝

## 제안 문서

- `rfcs/TEMPLATE.md` 를 복사해서 씁니다.
- 파일 이름은 바꾸는 내용을 영어 소문자와 하이픈으로 적습니다(`ban-nested-ternary.md`). 순번은 붙이지 않습니다.
- 근거에는 측정한 값과 실행한 명령, 읽은 문서의 이름과 주소를 적습니다. 확인하지 않은 것은 확인하지 않았다고 적습니다.
- 쓰는 저장소에서 지금 통과하는 코드가 변경 뒤에 실패하게 되는지를 적습니다.

## 받아들이기

- RFC 는 pull request 로만 받습니다. 이 저장소는 협업자만 pull request 를 열 수 있습니다.
- 저장소 관리자가 pull request 를 `master` 에 머지하면 RFC 를 받아들인 것입니다.
- 받아들이지 않는 RFC 는 pull request 를 닫고, 닫는 이유를 pull request 에 적습니다.
- 머지된 제안 문서는 고치지 않습니다. 받아들인 내용을 다시 바꾸려면 새 RFC 를 올리고, 새 제안 문서에 이전 제안 문서의 파일 이름을 적습니다.

## 쓰는 저장소에 전달

받아들인 변경은 `@pleand-inc/style-guide` 패키지의 다음 버전에 실립니다. 게시 방법은 저장소 루트의 `README.md` 에 있습니다. 쓰는 저장소는 패키지의 버전을 올려 변경을 받습니다.
