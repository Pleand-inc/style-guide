# 규칙 문서와 예시 문서를 패키지에 넣습니다

## 바꾸는 것

지금 패키지에는 규칙 문서가 없습니다. 이 RFC 뒤에는 패키지가 두 문서를 담습니다.

- `rules/RULES.md`: 코드 규칙의 본문입니다.
- `rules/EXAMPLES.md`: 규칙마다 규칙에 어긋난 코드와 규칙에 맞는 코드의 짝입니다.

쓰는 저장소는 `node_modules/@pleand-inc/style-guide/rules/` 에서 두 문서를 읽습니다.

두 문서는 새로 쓴 것이 아니라 사내 저장소에서 써 온 문서를 옮긴 것입니다. 옮기면서 바꾼 것은 다음과 같습니다. 규칙의 뜻을 바꾼 문장은 없습니다.

- 가져오기 경로 규칙의 문장과 예시에 있던 사내 저장소의 패키지 이름과 폴더 이름을 `@acme`, `apps/web` 같은 예시 이름으로 바꿨습니다.
- 예시의 이메일 주소를 `example.com` 주소로, 사내 코드의 함수 이름, 바인딩 이름, 캐시 키를 예시용 이름으로 바꿨습니다.
- 테스트의 가짜 객체 예시에서 지운 키를 모으는 곳을 빈 배열에서 `Set` 으로 바꿨습니다. 맞는 코드로 적힌 블록이 `biome/shared.json` 의 `style/useArrayLiterals` 에 걸렸기 때문입니다. 빈 배열은 `new Array<string>()` 으로 만들면 이 규칙에 걸리고, `const deleted: string[] = []` 로 만들면 초기값이 있는 변수에 타입을 적지 않는다는 규칙에 걸립니다.
- 에이전트 도구가 읽는 머리말을 뺐습니다.

## 이유

규칙의 원본을 이 저장소 한 곳에 두고 RFC 로 바꾸기 위해서입니다. 쓰는 저장소는 규칙 문서를 복사해 두지 않고 패키지의 버전을 올려 받습니다.

## 근거

- `rules/EXAMPLES.md` 의 `ts` 코드 39개를 블록마다 파일로 뽑아 TypeScript 6.0.3 으로 컴파일했습니다. `tsconfig/web.json` 을 받은 설정에서 오류가 없었고, 이름을 바꾸기 전의 문서도 같은 설정에서 오류가 없었습니다. 예시가 쓰는 `zod` 4.6.5, `jose` 6.2.12, Cloudflare Workers 런타임의 타입 선언을 함께 두고 컴파일했습니다.
- 같은 검사에서 가져오기 경로의 별칭 대응을 빼면 `TS2307` 로 실패합니다. 검사가 블록을 실제로 컴파일한다는 뜻입니다.
- 39개 블록을 `biome/shared.json` 으로 lint 했습니다. 어긋난 코드로 적힌 블록에서 진단 8건이 나왔고, 모두 그 블록이 어기는 규칙의 진단입니다. 맞는 코드로 적힌 블록에서는 진단이 없습니다.
- `npm pack --dry-run` 이 두 문서를 목록에 냅니다.

확인하지 않은 것은 다음과 같습니다.

- 예시의 컴파일 확인과 lint 확인은 이 변경에서 한 번 손으로 했습니다. `npm test` 는 예시를 컴파일하지도 lint 하지도 않습니다.
- 규칙 문서는 티켓 규칙에서 통합 브랜치의 이름을 `origin/develop` 으로 적고 있습니다. 다른 이름의 통합 브랜치를 쓰는 저장소에 맞추는 일은 별도 RFC 로 정합니다.

## 쓰는 저장소에 미치는 영향

- 규칙 문서를 자기 저장소에 복사해 두던 저장소는 복사본을 지우고 패키지의 문서를 읽게 합니다.
- 가져오기 경로 규칙의 `@acme` 는 자기 저장소의 패키지 이름으로 읽습니다.
