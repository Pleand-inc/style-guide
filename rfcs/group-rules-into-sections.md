# 규칙 문서의 항목을 종류별 절로 나눕니다

## 바꾸는 것

지금 `rules/RULES.md` 는 절이 셋입니다. 핵심 원칙 절에 항목 4개, 작성 가이드 절에 항목 12개, 타입 절에 항목 12개가 있습니다. 이 RFC 뒤에는 절이 일곱입니다. 항목의 문장은 바꾸지 않고 자리만 옮깁니다. 항목 앞의 이름표도 그대로 둡니다. 더하는 것은 `##` 제목뿐입니다. 절마다 두는 머리말, 표, 분류 표시, 예시 코드, 링크, 이력은 더하지 않습니다.

| 이 RFC 뒤의 절 | 항목 | 지금 있는 절 |
|---|---|---|
| 핵심 원칙 | 중복 제거, 단일 책임, 의도 드러내기, 단순함 | 핵심 원칙 |
| 이름과 함수 | 의미 있는 이름, 작은 함수, 작은 단위, 삼항 연산자 | 작성 가이드 |
| 모듈과 값 | 가져오기 경로, 스프레드와 그 하위 항목 넷 | 작성 가이드 |
| 주석과 변경 이력 | 주석, 이력, 티켓 만들기, 티켓 고치기, 티켓의 상태, 티켓 읽기 | 작성 가이드 |
| 타입 | 타입 단언과 non-null 단언, `any`, 반환 타입과 초기값이 있는 변수의 타입, 근원 타입, 값이 없을 수 있는 속성과 변수, `enum`, 리터럴 유니온 타입, 이미 있는 타입에서 만드는 타입, 유틸리티 타입 | 타입 |
| 외부 입력 | zod 스키마로 검증하는 항목 | 타입 |
| 타입 검사 성능 | 컴파일 시간을 늘리는 네 가지 타입과 그 하위 항목 넷, `tsc --extendedDiagnostics` 로 확인하는 항목 | 타입 |

절 안에서 항목의 순서는 지금과 같습니다. 타입 절은 옮겨 가는 세 항목을 뺀 아홉 항목을 지금 순서대로 둡니다.

문서 첫 문단의 범위 문장 하나를 고쳐 씁니다. 여섯 항목이 모두 주석과 변경 이력 절로 가므로 두 문장이 가리키는 항목은 같습니다.

- 지금: 작성 가이드의 주석, 이력, 티켓 만들기, 티켓 고치기, 티켓의 상태, 티켓 읽기 항목은 `apps/`, `packages/`, `scripts/` 아래의 JavaScript 파일과 주석을 쓸 수 있는 설정 파일에도 적용합니다.
- 이 RFC 뒤: 주석과 변경 이력 절의 항목은 `apps/`, `packages/`, `scripts/` 아래의 JavaScript 파일과 주석을 쓸 수 있는 설정 파일에도 적용합니다.

`rules/EXAMPLES.md` 는 바꾸지 않습니다. 그 문서의 `##` 항목은 `rules/RULES.md` 의 절 이름을 적지 않습니다.

## 이유

저장소 관리자가 규칙 문서의 구조가 너무 평평하다고 했습니다. 항목 28개가 절 셋에 들어 있어서 종류가 다른 항목이 한 절을 나눠 씁니다.

- 작성 가이드 절에는 코드의 모양을 정하는 항목, 모듈 경로 항목, 값 복사 항목, 주석과 이력 항목, 네 단계로 이어지는 티켓 절차가 함께 있습니다. 코드의 모양을 정하는 항목은 의미 있는 이름, 작은 함수, 작은 단위, 삼항 연산자입니다.
- 타입 절에는 타입 설계 항목, zod 로 외부 입력을 검증하는 항목, 컴파일 시간을 다루는 항목 둘이 함께 있습니다.

그래서 범위 문장이 JavaScript 파일에도 적용하는 항목 여섯 개를 하나씩 이름으로 불러야 했습니다. 절로 나누면 절 이름 하나로 가리킵니다.

`rfcs/README.md` 는 규칙의 뜻을 바꾸지 않는 변경에 RFC 가 필요하지 않다고 적지만, 이 변경은 저장소 관리자가 요청했고 범위 문장 하나를 고쳐 쓰므로 RFC 로 올립니다.

## 근거

2026-10-07 에 Node 26.10.0 과 Biome 2.5.15 로 확인했습니다.

- 항목이 빠지거나 바뀌지 않았는지는 옛 파일과 새 파일의 불릿 줄을 정렬해 비교했습니다. 들여쓴 하위 불릿도 포함합니다. 출력은 비어 있었고 종료 코드는 0 이었습니다. 두 파일 모두 불릿 줄이 36개입니다.

  ```sh
  git show HEAD:rules/RULES.md | grep -E '^ *- ' | sort > "$TMPDIR/bullets-old.txt"
  grep -E '^ *- ' rules/RULES.md | sort > "$TMPDIR/bullets-new.txt"
  diff "$TMPDIR/bullets-old.txt" "$TMPDIR/bullets-new.txt"
  ```

- 불릿 줄과 `##` 제목 줄을 뺀 나머지 줄을 같은 방법으로 비교하면 범위 문장 한 줄만 다릅니다.
- `git diff rules/RULES.md` 가 지운 줄은 셋입니다. 옛 범위 문장, `## 작성 가이드` 제목, 옛 자리의 zod 항목입니다. 더한 줄은 고쳐 쓴 범위 문장, `##` 제목 다섯 개, 새 자리의 zod 항목, 제목 앞뒤의 빈 줄입니다.
- 옛 절 이름을 가리키는 곳은 다음 명령으로 찾았습니다. 바꾸기 전에는 `rules/RULES.md` 의 범위 문장과 `## 작성 가이드` 제목 두 곳에만 있었습니다. 바꾼 뒤에는 한 곳도 없습니다.

  ```sh
  grep -rn '작성 가이드' --exclude-dir=node_modules --exclude-dir=.git .
  ```

- `rules/RULES.md` 를 가리키는 다른 문서는 `README.md`, `process/branch-flow.md`, `rfcs/rule-documents.md` 입니다. 모두 파일 경로만 적고 절 이름은 적지 않습니다.
- `npm run test:flow` 24건과 `npm test` 26건이 모두 통과했고, `npm run typecheck` 는 오류 없이 끝났습니다. `test/` 와 `scripts/` 의 검사는 `rules/RULES.md` 를 읽지 않으므로, 이 검사들은 저장소의 다른 부분이 그대로인 것을 확인합니다.
- `npm pack --dry-run` 의 목록에 `rules/RULES.md` 가 있습니다.

확인하지 않은 것은 다음과 같습니다.

- 쓰는 저장소의 문서나 에이전트 지시가 "작성 가이드" 라는 절 이름을 적고 있는지는 확인하지 않았습니다. 이 저장소 밖은 보지 않았습니다. 쓰는 저장소에서 위의 `grep` 을 실행하면 알 수 있습니다.

## 쓰는 저장소에 미치는 영향

지금 통과하는 코드는 이 변경 뒤에도 통과합니다. 규칙의 뜻이 바뀐 문장이 없고, lint 설정, 포매터 설정, TypeScript 설정도 바뀌지 않기 때문입니다.

- 쓰는 저장소는 코드를 고치지 않습니다. 패키지의 버전을 올리면 `node_modules/@pleand-inc/style-guide/rules/RULES.md` 에서 새 절을 읽습니다.
- 쓰는 저장소의 문서나 에이전트 지시가 "작성 가이드" 절 이름을 적고 있으면, 그 항목이 옮겨 간 절의 이름으로 바꿉니다. 이름과 함수, 모듈과 값, 주석과 변경 이력 가운데 하나입니다.
- JavaScript 파일과 설정 파일에도 적용하는 항목은 바꾸기 전과 같은 여섯 항목입니다.
