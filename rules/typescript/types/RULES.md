# 타입

- 타입 단언(`값 as 타입`)과 non-null 단언(`값!`)을 쓰지 않습니다. `as const` 는 예외입니다.
- `any` 타입을 쓰지 않습니다.
- 함수의 반환 타입과, 초기값이 있는 변수의 타입은 적지 않습니다. TypeScript 가 추론합니다. 값이 특정 타입에 맞는지 확인할 때는 `satisfies` 를 씁니다. 함수가 돌려주는 값이 특정 타입에 맞는지 확인할 때는 `return` 식에 `satisfies` 를 붙입니다. 이름을 붙여 선언한 타입에 맞아야 하는 객체를 변수에 담거나 `return` 할 때 `satisfies` 를 붙입니다. 함수의 인자로 바로 넘기는 값에는 붙이지 않습니다.
- 근원 타입은 다른 타입으로부터 만들지 않은 타입입니다. 근원 타입은 이름을 붙여 한 번만 선언합니다. 구조가 같은 타입을 두 번 선언하지 않습니다. 함수 하나의 인자에서만 쓰는 객체 타입은 인자 자리에 직접 적어도 됩니다. 두 곳 이상에서 쓰는 객체 타입에는 이름을 붙입니다.
- 값이 없을 수 있는 속성과 변수에만 `?` 와 `| undefined` 를 씁니다.
- `enum` 을 쓰지 않습니다.
- 가질 수 있는 값이 정해진 자리에는 `string` 이나 `number` 를 쓰지 않고, 그 값을 모두 나열한 리터럴 유니온 타입을 씁니다. 값의 목록은 `as const` 로 한 번만 적고, 유니온 타입은 그 목록에 `typeof` 를 적용해 만듭니다. 실행 중에 값의 목록을 읽는 코드가 없으면 `as const` 목록을 만들지 않고 리터럴 유니온 타입만 선언합니다.
- 이미 있는 타입이나 값으로 표현할 수 있는 타입은 직접 선언하지 않고 그 타입이나 값으로부터 만듭니다. 만들 때는 generics, `keyof`, `typeof`, indexed access 타입, conditional 타입, mapped 타입, template literal 타입을 씁니다. `string`, `number`, `boolean` 하나로 적는 속성의 타입은 그대로 적습니다. 객체 타입, 유니온 타입, 리터럴 타입은 이미 있는 타입에서 가져옵니다.
- TypeScript 가 전역으로 제공하는 유틸리티 타입으로 만들 수 있는 타입은 유틸리티 타입으로 만듭니다.
